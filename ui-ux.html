Case study 01

MediCompanion

MediCompanion keeps families close to a relative in a care home. I led its interface from the first flow to the finished screens, in English and Arabic, as Creative and Design Lead of the team that reached the global Top 20 at Harvard HSIL.

Project
MediCompanion, family app
Role
Creative Lead and Head of Media, in charge of UI, UX and the front end
Status
Ongoing. Working towards the first working, medical-grade MVP.
Tools
Figma, then a clickable prototype in the browser
Languages
English, Egyptian Arabic and Modern Standard Arabic
Year
2026

Design decisions

  1. Every state is designedA suspended account, a locked sign in, no connection, a country not yet served: each one has its own screen and a clear next step, not a generic error.
  2. Arabic first, not Arabic laterThe layout mirrors fully for right to left. Arabic has no neutral form of address, so the app asks how to speak to you and only uses the answer for that.
  3. Consent in plain wordsWhat is required and what is optional is set out before anything is recorded, and the app asks again whenever the terms change.
  4. Errors that say what happenedPassword rules tick off as you type, and a failed sign in tells you how many attempts are left before it locks.

Case study 02

Galala Scholar

A research portal for Galala University: one place to find the university's publications, conference work and researcher profiles, and a workspace where its researchers keep their own record up to date.

Project
Galala University Scholar
Client
Galala University, freelance commission
Role
UI and UX design
Scope
Search, researcher profiles, research outputs, faculty pages and the researcher workspace
Screens
Desktop and phone, English and Arabic
Year
2026

Design decisions

  1. Search comes firstThe home page is a search box and four figures, not a welcome message. One field covers researchers, outputs and events, with popular topics underneath to start a first-time visitor off.
  2. A profile built in small stepsA researcher completes a profile through a short checklist with a time estimate on each step, such as adding a photo or connecting ORCID, in place of one long form.
  3. The same record on any screenResult lists, filters and profile pages reflow from a wide monitor down to a phone without dropping a field.
  4. The university's identity as a systemColour, type and components follow the Galala University visual identity, so every page reads as one product.

Case study 03

This portfolio

Web design and development. The example is the site you are reading. I designed it, then built it in plain HTML, CSS and JavaScript, with no template, framework or page builder underneath.

Project
This portfolio
Role
Design, front-end build and motion
Stack
HTML, CSS and JavaScript. No framework, no build step.
Year
2026

How it is built

  1. Nothing underneath itOne HTML file, one stylesheet, one script. There is nothing to install, compile or keep updated, and it goes live by copying a folder.
  2. Motion with a job to doThe logo opening, the rolling headline, the logo wall and the footer wordmark are written in CSS and the Web Animations API, and each one pauses when it is off screen.
  3. Quick on a phoneImages ship in several sizes so each screen downloads only what it needs, anything below the fold loads late, and video waits until it is in view.
  4. Usable by everyoneReal headings and landmarks, a visible focus ring on every control, a skip link, and native dialog and details elements, so the content still reads with JavaScript off.
